## 1. 背景与问题

dsh-TUI 是 DeepSeek Harness 的终端界面应用。它在 0.19.0 内置了：

- `/skills`：**只读**技能目录 picker（回车把 `/name` 回填到输入框）；
- `/mcp`：MCP 状态报告，以及取决于后端能力的 reconnect / toggle；
- `/plugin`：插件的安装、启停、卸载；
- `/settings`：可被插件扩展的设置屏。

这些入口都没有解决「**技能与 MCP 的日常管理**」：

1. **技能**：只能看目录，不能在 TUI 内启停、删除、添加、分组、按全局/工作区查看；用户要自己 `cd ~/.dsh/skills`、改文件名、手工建目录。
2. **MCP**：只能看状态；新增/编辑/删除必须手改 profile 的 `cordis.patch.yml`，且要理解 loader 行、`!!js`、`env/headers`、`disabled` 等概念，门槛高、易写坏。
3. **全局 vs 工作区**：技能天然分全局根与项目根，但 TUI 没有可视化区分；MCP 只有 profile 级配置，这点必须向用户讲清楚（见 §4.3）。
4. **分组与批量**：用户经常需要「把这组技能整体关掉」「把 MCP 按项目分组」，现有入口完全不支持。

web 版 [`dsh-skill-mcp-panel`](https://github.com/Fishquito7/dsh-skill-mcp-panel)（DSH web 侧边栏插件）已经验证了「直接操作技能磁盘文件 + 受管改写 profile patch」的可行性与坑；本项目把这套能力做到 dsh-TUI 的终端场景里，并**与 web 版共享同一套磁盘约定**，避免两端互相看不见对方的状态。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 | 可观察结果 |
| --- | --- | --- |
| G1 | **统一入口** | TUI 内 `/skill-mcp` 打开全屏管理场景，技能与 MCP 在同一界面切换 |
| G2 | **技能全生命周期可视化** | 列表、详情、启停、删除、添加、迁移、分组、按全局/工作区筛选，全部不需要离开 TUI |
| G3 | **MCP 全生命周期可视化** | 列表、状态、启停、新增、编辑、删除、诊断，不需要手改 YAML |
| G4 | **热加载** | 除明确标注的例外，操作后无需重启 TUI；界面如实显示「已保存，热加载中 / 已生效 / 需重启」 |
| G5 | **安全与可逆** | 不损坏用户文件；危险操作二次确认；删除进回收站可撤销；MCP patch 写前备份、字节保真 |

### 2.2 非目标（首版明确不做）

| 不做 | 原因 |
| --- | --- |
| Web UI / 浏览器面板 | 本项目是 TUI 插件；web 版已存在 |
| 插件安装/卸载/更新 | 由 dsh-TUI 自带 `/plugin` 负责，不重复实现 |
| 技能正文编辑器 | 只查看 + 导入/删除/启停；正文编辑交给用户编辑器 |
| 嵌套分类目录技能发现 | DSH 内核只发现一层；跟 web 版多扫会显示「面板有、模型看不到」的幽灵技能 |
| 工作区级 MCP | 内核没有「按工作区存 MCP 配置」的容器（见 §4.3） |
| MCP OAuth 登录、单工具禁用 | 参考版有，但依赖 web/宿主专有链路；首版不做，列入 P2 |
| 伴随 CLI（`dsh-panel` 一类） | 首版只做 TUI 交互；是否提供另议 |
| 自动更新插件自身 | 走 `/plugin` 与 npm 发布流程 |
| 修改 DSH 内核 / 依赖私有 `@deepseek-ai/*` 实现 | 只消费公开服务与 dsh-TUI 公开子路径 |

## 3. 用户与场景

**主要用户**：在本机使用 dsh-TUI 的开发者 / agent 用户，已装有一个或多个 profile，日常有多个项目工作区。

**典型场景**：

| 场景 | 用户动作 | 期望结果 |
| --- | --- | --- |
| S1 关掉暂时不用的技能 | `/skill-mcp` → 技能页 → 找到技能 → 空格 | 技能从模型可见列表消失，下一步请求前生效；可再开 |
| S2 把一个技能从全局挪到当前项目 | 技能页 → `m` 迁移 → 选目标工作区 | 真实移动文件；目标作用域可用，全局不再列出该实例 |
| S3 给项目装一个技能 | 技能页 → `a` 添加 → 输入本地路径（.md / 目录）→ 选作用域 | 校验 frontmatter、查重后落盘；立即出现在列表 |
| S4 按分组批量停用 | 分组页 → 选组 → 批量停用 | 组内技能逐个停用，失败逐条报告，成功的保留 |
| S5 新增 MCP server | MCP 页 → `a` → 选 stdio/http → 填表 | 写入当前 profile patch 的受管块；HMR 后连接、工具可用 |
| S6 停用一个 MCP | MCP 页 → 空格 | 官方 `pluginManager` 写 disabled；连接断开、工具注销；可再启用 |
| S7 误删恢复 | 技能页 → `u` 撤销 / 回收站页 | 从回收站恢复到原作用域；MCP 从备份恢复对应行 |
| S8 排查「为什么模型看不到我的技能」 | 诊断页 | 显示发现根、frontmatter 是否合法、是否被同名遮蔽、是否停用、`.git` 根判定 |

## 4. 术语、作用域与数据真源

### 4.1 术语

| 术语 | 含义 |
| --- | --- |
| 技能（skill） | 一个 `SKILL.md` 目录束或单文件 `<name>.md`，含 frontmatter（`name` + `description` 必填） |
| 技能实例 | **（技能名, 作用域根）** 二元组；同名技能可同时存在于全局与多个工作区 |
| 作用域（scope） | 技能的发现根类别：全局（用户根、bundled）或工作区（项目根）；MCP 的配置层：当前 profile / home |
| 工作区 | 从会话 `cwd` 向上最近的含 `.git` 的祖先目录（DSH 的 projectRoot 规则），**不是** TUI 的 workspace 记录 |
| MCP server | profile patch 中一条 `name: '@deepseek-ai/dsh-mcp-client'` 的 loader 行 |
| 受管块 | 本插件在 patch 文件里维护的注释围栏区块，只放本插件新增的行 |
| 热加载 | 无需重启进程/会话，改动在下一步或 1–2 秒内生效 |
| 回收站 | 本插件私有目录，存放软删除的技能实体与 MCP 行快照 |

### 4.2 技能作用域与发现规则（必须与 DSH 内核一致）

发现根按优先级（数值小者优先）：

| rank | 类别 | 路径 | 作用域 |
| --- | --- | --- | --- |
| 100 | `project-dsh` | `<projectRoot>/.dsh/skills` | 工作区 |
| 200 | `project-agents` | `<projectRoot>/.agents/skills` | 工作区 |
| 300 | `custom` | profile 配置 `customSkillDirs`（当前未配置） | 全局（自定义） |
| 400 | `user-dsh` | `$DSH_HOME/skills`（默认 `~/.dsh/skills`） | 全局 |
| 500 | `user-agents` | `$DSH_AGENTS_HOME/skills`（默认 `~/.agents/skills`） | 全局 |
| 600 | `bundled` | `DSH_BUNDLED_SKILL_DIR` | 全局（只读） |

规则：

1. 目录束只认 `<root>/<name>/SKILL.md`；单文件只认根层 `<root>/<name>.md`。**不递归**分类目录。
2. frontmatter 必须 `---` 包裹；`name` 为 kebab-case、`description` 必填；非法值会导致该技能被**静默丢弃**——面板必须把「文件存在但不可用」显示出来并说明原因。
3. 用户根下的 `.system/` 子树被内核跳过，本插件也不把它当技能。
4. **同名裁决**：近层（工作区）遮蔽远层（全局）；同层按 rank → provider 注册序。面板显示「生效版本」并标注被遮蔽的实例。
5. **projectRoot 必须用 `cwd` 向上找最近 `.git` 的规则**；若 TUI workspace 指向 git 子目录，面板显示的「工作区」与内核实际根可能不同——UI 必须展示**实际发现根路径**，不能只显示 workspace 标题。
6. **dsh-TUI 在 host 层禁用了 `skill-filesystem`**（技能由 preset 在 agent 作用域挂载），因此 host 插件不能依赖 `ctx.skills.list()` 拿完整列表；**列表以按上述规则扫盘为准**，`ctx.skills` 只做可选交叉校验。**（2026-11-08 真机实测确认：host 层 `ctx.skills.list()` 返回空数组、`snapshot().skills` 为空，见 [`research/05`](research/05-m0-real-machine-probe.md) §2 Q7。）**

### 4.3 MCP 作用域（必须如实告知的限制）

- 一个 MCP server = 一条 loader 行，配置只存在于 patch 文件：
  - **当前 profile**：`$DSH_HOME/profiles/<name>/cordis.patch.yml` —— 首版**可写**，是 MCP 管理的主域；
  - **home 层**：`$DSH_HOME/cordis.patch.yml` —— 跨 profile 的全局层，优先级高于 profile patch；**首版只读展示**，标注「全局层；改动会影响所有 profile，请手工编辑」。
- **没有工作区级 MCP**：DSH 0.2.x 没有按工作区存插件配置的容器。因此本插件的 MCP 页提供：
  - 「当前 profile」列表（可管理）；
  - 「home 层（全局）」列表（只读，展示覆盖关系）；
  - 工作区切换器对 MCP 页显示**不可用说明**，而不是伪造一个工作区视图。
- 若未来上游提供按工作区/按 agent 组合 MCP 的接口，再升级本插件的 MCP 作用域模型（见 §12 Q1）。

### 4.4 热加载矩阵（面向用户承诺的边界）

| 操作 | 机制 | 需重启？ | 用户可见生效时机 |
| --- | --- | --- | --- |
| 技能新增/删除/迁移/停用/启用 | 文件系统 watcher 失效 | 否 | 下一步模型请求前（catalog 替换） |
| 技能正文修改 | `get()` 每次现读 | 否 | 下次加载/查看 |
| 技能 frontmatter 修改 | watcher 失效 | 否 | 下一步 |
| MCP 启用/停用 | `pluginManager.setPluginEnabled` 或 patch `disabled` | 否 | 秒级（HMR/重载） |
| MCP 新增/编辑/删除 | patch 写入 + HMR 重组合 | 否 | **实测 ≈2.0–2.5s**（写入完成→loader 行可见 2.50s；含 `awaitWriteFinish` 2s），见 research/05 §2 Q11 |
| 插件自身偏好（分组、视图） | 本插件 JSON | 否 | 立即 |
| 改到宿主依赖图/包目录被移动等 | 内核判定 | **是**（`restart-required`） | 必须提示用户重启 |

> UI 不得笼统承诺「全部即时生效」：保存后显示「已保存，热加载中…」，轮询到生效再改为「已生效」；超时显示「可能需检查日志/重启」。
>
> **2026-11-08 真机实测补充**：场景内 `tuiDialogs` / `tuiToast` 均不可用（dialog 立即静默取消、toast 无 sink），确认/输入必须场景内自绘、反馈用场景内状态条；MCP 启停不要依赖 `pluginManager` 阻塞调用（见 [`research/05`](research/05-m0-real-machine-probe.md)）。

## 5. 功能需求

> 标记 **P0** = 首版必须；**P1** = 首版尽量，可降级；**P2** = 明确延后。
> 每个 FR 的验收映射见 §9。

### FR-1 入口与场景（P0）

- `/skill-mcp`（命令名待最终确认；需避开内置 `/skills`、`/mcp`、`/plugin`、`/panel`）注册命令，打开场景 id `skill-mcp-panel`。
- 场景为全屏 React/Ink 视图，独占键盘；`Esc` / `q` 关闭并返回打开前的屏幕。
- 场景打开不产生会话事件、不写入 transcript。
- 可选 `Ctrl+Shift+M` 直达（必须确认不在宿主保留位；不替代命令入口）。
- 宿主 `tuiScenes` 缺席（旧版 dsh-TUI）时，命令返回可读错误，不崩溃、不影响 TUI 启动。

### FR-2 技能列表（P0）

- 顶部页签：**技能 / MCP / 分组 / 诊断**；默认落在上次停留页（持久化到本插件配置）。
- 技能页左侧（宽屏）或顶部 chip（窄屏）为**作用域切换**：全局、当前工作区、其他已知工作区（来自 `ctx.tuiWorkspaces`，若可用）。
- 列表行显示：状态（启用/停用/无效）、技能名、来源（project-dsh / project-agents / user-dsh / user-agents / bundled）、作用域、分组标签、frontmatter 是否合法、是否为被遮蔽实例。
- 支持按名称/描述搜索（`/` 进入搜索态）、按分组筛选、按状态筛选。
- 刷新：进入页面时读盘；收到 `skills/change`（若可订阅）或手动 `r` 时刷新；外部文件变化后列表在下次进入/刷新时一致。
- 空状态：无任何技能根时给出「如何添加/根路径不存在」的说明。
- **不得**把内核不发现的嵌套目录技能列出来（避免幽灵条目）。

### FR-3 技能详情（P0）

- 选中行右侧/下方显示：完整路径、作用域根、rank、生效状态、被遮蔽的同名实例、frontmatter 关键字段、正文前 N 行。
- 正文按纯文本展示（场景无 Markdown 渲染能力）；控制字符、超长行需消毒/折行，按 terminal cell 计算宽度。
- 提供「打开所在目录」的路径复制文本（TUI 内不做系统文件管理器弹窗；可给复制提示）。
- 可查看全文（滚动），不编辑。

### FR-4 技能启停（P0）

- `Space` 切换选中技能实例的启用状态：
  - 目录束：`SKILL.md` ↔ `SKILL.md.disabled`；
  - 单文件：`<name>.md` ↔ `<name>.md.disabled`；
  - 与 web 版保持**同一约定**，保证两端互相识别。
- 只操作**选中的（名, 作用域）实例**；同名其他作用域实例不受影响。
- bundled / 插件自带技能只读：显示锁定状态，不允许启停/删除（可提供「隐藏显示」偏好）。
- 文件被外部占用/权限失败：显示错误，保持原状，不重试写坏文件。
- 停用后界面状态更新并提示「已停用，热生效」；若 watcher 未生效（超时），提示刷新/重启。

### FR-5 技能删除（P0，软删除 + 撤销）

- 删除前二次确认，确认页必须显示：技能名、作用域、完整路径、影响（「将移入回收站，可撤销」）。
- 删除 = 将整个技能实体（目录或单文件）**移动**到本插件回收站：
  `~/.dsh-tui/skill-mcp-panel/trash/<ISO 时间戳>/<作用域键>/<技能名>/…`，并写入回收站清单（原名、原根、删除时间）。
- 支持撤销：从回收站恢复到原根；若原位置已被同名占用，提示冲突并允许选择「取消 / 覆盖前备份 / 恢复到其他作用域」。
- 回收站保留策略：默认 7 天或最近 100 条（取先到者），启动时清理过期项；清理前在诊断页可见。
- bundled 技能拒绝删除。
- 不删除技能根目录本身（只删技能实体）；不触碰 `.system/`。
- 权限/跨设备 rename 失败时回退「复制 + 校验 + 删除源」，失败则整体回滚并报告。

### FR-6 技能添加/导入（P0，zip 为 P1）

- 入口 `a`；输入源为**本地绝对路径**（TUI 无浏览器文件选择器），支持：
  - 单个 `<name>.md` 文件；
  - 技能目录束（含顶层 `SKILL.md`）；
  - 含多个技能的父目录（递归发现后逐条导入，P1 可做）；
  - `.zip`（P1，可选依赖 `fflate`）。
- 目标作用域选择：全局（`~/.dsh/skills`）或当前工作区（`<projectRoot>/.dsh/skills`）；默认当前工作区；若当前会话没有可判定的 projectRoot（无 cwd 兜底），默认全局并明确提示。
- 写入前校验：frontmatter 合法（`name` kebab-case、`description` 非空）、路径不逃逸、文件数量/大小上限（建议 200 文件 / 8 MiB，单 `SKILL.md` ≤1 MiB）、目标作用域内无同名。
- 冲突策略：目标作用域内同名 → 跳过并报告；跨作用域同名 → 允许并提示（内核按作用域裁决）。
- 批量导入：逐条报告成功/跳过/失败原因，单条失败不影响其余。
- 导入完成刷新列表；若目标根不存在则创建（并说明会触发内核 watch 轮询）。

### FR-7 技能迁移/复制（P1）

- `m` 打开迁移流程：源实例 → 目标作用域（可多选）→ 复制或移动。
- 先校验目标无同名/可写，再执行；移动 = 复制成功后删源；任一步失败整体回滚。
- 迁移不改变技能内容；不修改 frontmatter。
- 迁移后两端列表刷新；操作记录进入诊断/撤销（撤销可复用回收站机制：移动的源进入回收站）。

### FR-8 分组（P0）

- 分组是**显示层元数据**，不写技能目录、不改变技能发现。
- 存储：与 web 版共享 `$DSH_HOME/skills/.system/skill-viewer/groups.json`（`version: 1`，`groups[id] = { name, scopes: { "global": [...], "<workspacePath>": [...] } }`）；读写均做容错（损坏 → 备份 + 空配置 + 诊断提示）。
- 能力：新建、重命名、删除分组；批量勾选加入/移出；按分组筛选列表；分组计数。
- 分组操作支持**批量动作**：对组内成员批量启用/停用/删除（删除仍走回收站与逐条报告）。
- MCP 页也支持分组，但**不写入共享的 `groups.json`**：MCP 分组存本插件配置（`~/.dsh-tui/skill-mcp-panel/config.json`），成员用「serverName + entryId」，避免扩展 web 版 schema 造成兼容问题。
- 空分组行为：新建后立即可见（不因无成员被删）；删除分组不动成员本身。

### FR-9 MCP 列表（P0）

- 数据来源：解析当前 profile 的 `cordis.patch.yml`，并以 `ctx.loader.entries()` 兜底/交叉校验（**实测 `pluginManager.listPlugins()` 恒为空，不能作为列表来源**）；`ctx.pluginManager` 只在能定位 entryId 时提供运行时状态。
- 行显示：serverName、transport（stdio / streamable-http）、启用状态、来源层（profile / home）、是否受管块内、entryId 尾号、工具数/连接状态（若可从宿主服务拿到）、是否重名、是否被更高层覆盖。
- 支持搜索、按状态/分组筛选、`r` 刷新。
- 解析失败（YAML 损坏）：页面进入错误态，显示文件路径与错误摘要，提供「查看原文/备份路径」，**不自动修复、不写文件**。
- 受管块标记失配：显示「受管块损坏」并提供只读诊断 + 修复向导（P1；修复前必须备份）。

### FR-10 MCP 启用/停用（P0）

- `Space` 切换（**2026-11-08 真机实测校正，D-9**：官方 API 对 patch 插入行不可用）：
  1. **主路径 = patch 文本编辑**：给目标行写/删 `disabled` 覆盖（受管块内、字节保真、写前备份），语义以参考版实现与实测为准；
  2. `ctx.pluginManager` 仅在「服务存在 + `listPlugins()` 能定位 entryId」时尝试 `setPluginEnabled(entryId, enabled)` 作为加速；**必须带超时**（实测失败耗时 ≈33s，返回 `failed/unknown-plugin`），超时/失败即回退 1；
  3. 不要在该调用上阻塞键盘：后台执行 + 状态条展示进度。
- 对 `disabled` 由 `!!js` 表达式控制的行：显示「由表达式控制」，不提供布尔开关。
- 结果处理：`applied` → 提示已生效；`restart-required` → 提示需重启并给出命令；`overridden` → 提示被 home 层覆盖；`failed` → 显示原因。
- home 层行只读：按钮禁用并说明「全局层，请在 `~/.dsh/cordis.patch.yml` 手工修改」。
- 操作后轮询运行时状态（上限约 10s），不要把「保存成功」当「已连接」。

### FR-11 MCP 新增（P0）

- 表单字段：
  - 必填：`serverName`（`[A-Za-z0-9_-]{1,32}`，当前 profile 内文件级不重复；运行时还要求所有活跃实例内唯一，重名会导致后加载实例失败，UI 需提示）、transport；
  - stdio：`command`、`args`（每行一个/空格分隔需明确）、`env`（KEY=VALUE，支持 `${ENV}` 语法）、`cwd`（可选）；
  - streamable-http：`url`、`headers`（KEY=VALUE，支持 `${ENV}`）；
  - 可选高级：`toolCallTimeoutMs`、`failOnStartupError`（若内核支持则透传，否则不显示）。
- 写入位置：当前 profile 的 `cordis.patch.yml` 的**本插件受管块**：
  `# >>> dsh-tui-skill-mcp-panel:mcp:begin` / `# <<< dsh-tui-skill-mcp-panel:mcp:end`；
  行 id 使用 `mcp-<serverName>` 前缀（冲突时加序号）。
- 写入流程：预校验 → 读取当前文件（与打开时比对，变化则提示重读）→ 获取锁 → 生成新文本 → 校验可解析 → 原子写（临时文件 + rename）→ 备份 → 释放锁 → 等待 HMR 生效。
- `${ENV}` 值必须格式化为 `!!js` 表达式并原样往返；**绝不在插件内求值/记录 env 值**；UI 与日志脱敏。
- 重名拒绝（新增时）；新增失败不留下半截文件。

### FR-12 MCP 编辑（P0）

- 选中行 `Enter` 进入编辑表单；表单回填已知字段；未知字段（如未来新增配置键）必须保留。
- 只允许编辑**当前 profile** 的行；home 层行只读。
- 保存时只重写目标行的 YAML 片段，**文件其余字节保持不变**；行内格式允许归一化，但 `!!js` 表达式、密钥引用、未建模键值必须语义保留。
- 保存前展示 diff 摘要（哪些键变化、是否含密钥），长表单/危险改动二次确认。
- 保存后流程同 FR-11（备份、原子写、等 HMR）。
- 若该行被 home 层同 id 覆盖，保存前提示「改动不会生效」，并允许取消。

### FR-13 MCP 删除（P0，备份 + 撤销）

- 二次确认，显示：serverName、entryId、所在层、是否会断开连接/注销工具。
- 删除 = 从 patch 中移除该行文本；删除前把整个 patch 文件备份到
  `~/.dsh-tui/skill-mcp-panel/backups/<时间戳>/cordis.patch.yml`，并在回收站清单中记录被删除行的原文与位置。
- 撤销：把行原文插回原位置（校验文件自删除后未被外部修改；若被修改则提示合并/取消）。
- 受管块删空时成对移除 begin/end 标记；块内/块外其他行逐字节保留。
- home 层行不允许删除。

### FR-14 MCP 诊断与测试连接（P1）

- 诊断：显示 profile 路径、home 路径、patch 可解析性、受管块状态、重复 id/serverName、被覆盖行、HMR 状态（若可探测）。
- 测试连接（P1 可选）：对选中 server 做一次性 MCP 握手并展示工具列表/错误；实现方式需在设计中确定（复用宿主依赖或临时挂载），**不作为首版验收硬项**；若实现，必须带超时与显式失败原因。
- 不启动长驻子进程、不在场景内同步阻塞。

### FR-15 批量与分组操作（P0/P1）

- 技能列表支持多选（`v` 标记）后批量：启用/停用/删除（回收站）/迁移（P1）。
- 分组页支持对整组执行同样的批量动作。
- 批量操作：逐条执行、逐条报告、单条失败不回滚已成功的条目（除非用户选择「全部失败即回滚」，P1）；操作前确认。
- 批量执行时显示进度（第 n/N 条），不阻塞键盘关闭（允许中途停止，P1）。

### FR-16 插件设置与视图偏好（P1）

- 通过 `ctx.tuiSettingsSections` 注册设置区块（若服务存在），字段建议：
  - 打开时默认页签（技能/MCP/分组/诊断）、默认作用域；
  - 是否显示 bundled/插件技能；
  - 回收站保留天数（1–90，默认 7）；
  - 危险操作确认开关（默认开）；
  - MCP 生效等待上限（秒，默认 10）。
- 设置命名空间由插件自己的 `ctx.settings` 支撑；服务缺失时用本插件配置 JSON 兜底，不崩溃。
- 视图偏好（列宽、上次选中项）存本插件配置，不进入 groups.json。

### FR-17 外部变更与并发（P0）

- 打开 MCP 页时记录 patch 文件 mtime/内容哈希；写前比对，若已被外部修改（web 面板/编辑器/其他 agent）：提示「文件已变化」并提供「重新加载 / 覆盖前备份」选择，**不静默覆盖**。
- 与 web 面板共用同一把锁文件 `<patch>.panel.lock`（约定同参考版）；获取超时约 5s，陈旧锁（>30s）可清理。
- 技能操作前重读目标文件；删除/迁移遇到外部改动时提示冲突。
- 分组文件写入使用「临时文件 + rename」；读取损坏时备份并回退空配置。

### FR-18 错误、空状态与诊断（P0）

- 所有错误必须在界面可见（底部错误条/诊断页），不用 `console.log`，不把异常抛给宿主。
- 错误信息包含：操作、对象、路径、原因摘要、下一步（重试/查看日志/手工修复）。
- 空状态区分：无技能、根目录不存在、全部被过滤掉（搜索/筛选）、无权限读取。
- 诊断页汇总：版本、宿主能力探测结果（哪些接缝可用）、路径、锁/备份/回收站状态。

### FR-19 帮助与快捷键（P0）

- `?` 打开场景内帮助（键位表 + 作用域说明 + MCP 限制声明）。
- 底栏/顶部显示当前可用键位（随上下文变化）。
- 危险操作确认页显示 `y/n`，`Esc` 取消。

## 6. 交互设计

### 6.1 布局（按终端内容宽度分档）

| 内容宽度 | 布局 |
| --- | --- |
| ≥ 110 | 四栏：作用域/分组 ｜ 列表 ｜ 详情/表单 ｜（可选）帮助 |
| 90–109 | 三栏：左侧作用域+分组折叠树 ｜ 列表 ｜ 详情 |
| 64–89 | 双栏：列表 ｜ 详情；作用域/分组做顶部 chip 行 |
| < 64 | 单栏 + 面包屑（列表 → 详情 → 返回），顶部显示当前作用域/分组 |

- 宽度按 **terminal cell** 计算（CJK/emoji 占 2 cell），不用 `string.length`；不用 `%` 宽度，按实际 `columns` 逐层传递。
- 长列表用 `ScrollBox`；列表行做**稳定截断**并按 cell 补齐，避免抖动。
- 场景不渲染 Markdown；技能正文用纯文本 + 折行。富文本预览（若做）放侧栏 Panel（v1.1 可选）。

### 6.2 键盘模型（场景自绘）

| 键 | 行为 |
| --- | --- |
| `↑/↓`、`j/k` | 列表选择（方向键即可完成核心导航） |
| `←/→`、`h/l` | 切换作用域：全部 / 工作区 / 全局 |
| `PgUp/PgDn`、`Home/End` | 详情/诊断滚动、列表翻页 |
| `Tab` / `Shift+Tab` | 切换栏/页签 |
| `Enter` | 进入详情/编辑/提交 |
| `Space` | 切换启用状态 |
| `a` / `d` / `m` / `g` / `u` | 添加 / 删除 / 迁移 / 分组 / 撤销 |
| `/` | 搜索 |
| `v` | 多选 |
| `r` | 刷新 |
| `?` | 帮助 |
| `Esc` / `q` | 返回 / 关闭；表单内 `Esc` 先取消编辑 |
| `y` / `n` | 确认/取消删除等危险操作 |

- 场景独占键盘；**不使用宿主 `tuiDialogs` 做场景内确认**（2026-11-08 实测：场景内与命令内调用都在 0ms 内静默返回取消值，界面无对话框；toast 也不可用）。确认与单行输入全部在场景内自绘。
- 多字符 paste 按整段插入处理；不逐字处理。
- **键盘完整可用、不依赖鼠标**；鼠标为增强：fullscreen 下尝试路由 `Box onClick`（页签/作用域/技能行）与 `onWheel`（列表/详情/诊断滚动），未收到鼠标事件时自动退回纯键盘。【待真机确认：插件场景是否收到鼠标事件（2026-11-08 已实现，待用户实机验证）】

### 6.3 状态与反馈

- 右下/底栏常驻：总数、当前筛选、选中项状态、热加载状态。
- 操作后 toast/状态条：`已保存，热加载中…` → `已生效` / `超时，请检查诊断`。
- 长操作（>300ms）显示进度或「处理中」；不在渲染路径做同步 I/O。
- 失败用红色错误条 + 可展开详情；不自动关闭。

### 6.4 文案与语言

- 首版 UI 文案：**英文键名/标签 + 中文说明**（或按 `channel` 语言切换，若宿主提供）。插件侧没有完整 i18n 接缝，先保证关键限制（MCP 作用域、热加载边界）用中文明确表达。
- 限制声明必须出现在：MCP 页顶部提示、帮助页、README。

## 7. 数据与存储

| 数据 | 位置 | 格式 | 生命周期 |
| --- | --- | --- | --- |
| 技能实体 | 各发现根（见 §4.2） | 文件/目录 | 用户所有；卸载插件不删 |
| 技能停用标记 | 同技能实体，文件名加 `.disabled` | 文件命名 | 同上 |
| 技能分组 | `$DSH_HOME/skills/.system/skill-viewer/groups.json` | JSON v1（与 web 版共享） | 卸载保留；损坏可重建 |
| MCP 分组 | `~/.dsh-tui/skill-mcp-panel/config.json`（`mcpGroups` 字段） | JSON（本插件私有） | 卸载保留 |
| MCP 配置 | 当前 profile `cordis.patch.yml` | YAML（保留 `!!js`） | 用户所有；写前备份 |
| MCP home 层 | `$DSH_HOME/cordis.patch.yml` | YAML | 首版只读 |
| 插件配置 | `~/.dsh-tui/skill-mcp-panel/config.json` | JSON（版本字段） | 卸载保留 |
| 回收站 | `~/.dsh-tui/skill-mcp-panel/trash/<时间戳>/…` + `manifest.json` | 技能实体 + 清单 | 过期清理 |
| MCP 备份 | `~/.dsh-tui/skill-mcp-panel/backups/<时间戳>/cordis.patch.yml` | 原文件副本 + 行快照 | 保留最近 N 份/天数 |
| 锁 | `<patch>.panel.lock`（与 web 版共用） | 文本（pid + 时间） | 超时/陈旧清理 |

写操作统一要求：

1. 写前读取并校验；写临时文件 → `rename` 原子替换；
2. YAML 写后重新解析校验，失败不提交；
3. 备份先于破坏性写；
4. 密钥/令牌不落日志、不进诊断输出；UI 默认脱敏；
5. 所有用户可见的「删除」必须可撤销或明确标注不可撤销（本版全部软删除）。

## 9. 验收标准

### 9.1 自动化（域层，必须）

- **AC-1** 技能扫描：构造临时根（全局/工作区/单文件/目录束/非法 frontmatter/重名/`.disabled`），断言列表、状态、生效实例与遮蔽关系符合 §4.2。
- **AC-2** 启停：断言 `SKILL.md` ↔ `SKILL.md.disabled` 往返、同名不同作用域互不影响、bundled 拒绝。
- **AC-3** 添加校验：非法 frontmatter、路径逃逸、超大文件、目标同名、跨作用域同名，断言逐条结果。
- **AC-4** 软删除/撤销：断言移入回收站、清单正确、恢复到原根、冲突处理、过期清理。
- **AC-5** 分组：技能分组读写 groups.json v1、损坏回退、批量加/移成员、空组行为、与 web 版格式兼容；MCP 分组读写插件配置。
- **AC-6** MCP 文本编辑：断言只改目标行、其余字节不变、`!!js` 原样往返、CRLF 保持、受管块增删成对、重复 serverName 双键定位、锁互斥。
- **AC-7** MCP 启停状态机：`applied`/`restart-required`/`overridden`/`failed` 的 UI 状态映射（可用假服务）。
- **AC-8** 并发：外部修改检测、写前比对、备份存在、失败不写坏文件。

### 9.2 真机验收（必须逐项手工执行并记录）

- **AC-9** 安装：`pnpm build` → `dsh plugin --profile dsh-tui add <path>` → 启动 TUI → `/skill-mcp` 可打开；卸载后 TUI 正常启动。
- **AC-10** 技能热加载：TUI 运行中新增/停用/删除技能，`/skills` 菜单与模型侧在下一步前反映变化；场景刷新后一致。
- **AC-11** MCP 热加载：TUI 运行中新增 stdio server（如 `npx -y @modelcontextprotocol/server-memory` 类），场景显示连接/工具状态，模型侧工具出现；停用后消失；无需重启。
- **AC-12** MCP `!!js`：配置 env 为 `${ENV_VAR}`，保存后重启/重载仍为表达式；密钥在 UI/日志中不出现明文。
- **AC-13** 撤销：删除技能与 MCP 行后各撤销一次，文件恢复且内容一致。
- **AC-14** 布局：在 <64、64–92、≥93 列三种宽度、inline 与 fullscreen 两种模式下完成列表-详情-表单操作，无溢出/截断错位。
- **AC-15** 与 web 版共存：同一台机器上 web 面板与 TUI 面板分别操作技能停用与 MCP 行，双方状态一致、无文件损坏、无丢行。
- **AC-16** 限制声明：MCP 页明确显示「无工作区级」、home 层只读；帮助页与 README 一致。

### 9.3 准入与发布（必须）

- **AC-17** `dsh-plugin.json` 通过固定 revision 的 manifest parser；`check:manifest` 与 `npm pack --dry-run` 断言通过；`files` 含 manifest。
- **AC-18** 准入清单 A–G 逐条自查记录（见 AGENT.md §8 与调研 01 §8）；`permissions: []` 与 `requires.contracts` 写法正确。
- **AC-19** `v*` tag 与 `package.json.version` 一致；`npm publish --provenance`（或受信发布）成功；GitHub Release 提供 tarball。

## 11. 风险与缓解

| 编号 | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| R-1 | 编辑 patch 损坏用户组合/丢行 | 高（可能让 TUI 起不来） | 字节保真编辑器、只改目标行、写前备份、写后解析校验、锁、与 web 版共用锁；先做文本层单测再上 UI |
| R-2 | HMR 生效延迟/失败被误报为成功 | 中 | 轮询运行时状态 + 超时提示；区分 saved/applied/restart-required |
| R-3 | 与 web 面板并发写 | 中 | 同一锁文件、写前 mtime/哈希比对、冲突提示 |
| R-4 | 技能发现规则漂移（上游改 rank/根） | 中 | 把发现规则集中在单一模块；启动时对已知根自检；文档标注适用版本 |
| R-5 | host 服务缺失/版本漂移（`pluginManager` 等非 dsh-TUI 文档化接缝） | 中 | 全部 `ctx.get(..., false)` 软探测 + 降级；诊断页显示能力 |
| R-6 | 场景无 Markdown、无成熟表单控件 | 低 | 首版纯文本 + 自绘输入；富文本留侧栏 Panel（v1.1） |
| R-7 | 命令名冲突（技能 slash 菜单/内置命令） | 低 | 选不易撞的名字；冲突时内置优先，UI 帮助说明 |
| R-8 | 删除/迁移不可逆焦虑 | 中 | 软删除 + 回收站 + 撤销 + 备份；确认页写清影响 |
| R-9 | MCP 测试连接/OAuth 范围膨胀 | 中 | 首版不做 OAuth；测试连接 P1 可选、非验收硬项 |
| R-10 | 上游将来提供 workspace MCP 或内置 mcpManager | 中 | 解耦配置层与服务命名；跟踪 issue；不注册 `mcpManager` |
